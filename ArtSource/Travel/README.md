# 이동 유형 모션과 UI

## 원본 토끼 유지

사용자 피드백에 따라 토끼의 디자인을 다시 생성하지 않는다. 이미지 생성으로 시도한 시안은 채택하지 않았으며 프로젝트 자산으로 참조하지 않는다.

`RabbitTravelArt`는 기존 `Art.Rabbit(costume, Pose.Idle0)`의 픽셀을 사용한다. 얼굴, 눈, 귀, 목의 붉은 천과 몸통을 하나의 레이어로 보존한다. 발과 팔의 위치, 뒤로 늘어진 천의 자세만 바꾼다. 머리/목을 따로 움직이거나 전체 캐릭터를 회전·늘여서 모션을 만들지 않는다. 기존 `CleanIdleEyes` 처리도 변경하지 않았다.

각 유형은 8프레임이다: 진입 0–1, 이동 2–5, 마무리 6–7. 날개형은 기존 붉은 천이 같은 색의 망토처럼 펼쳐진다. 굴파기 중에는 원본 귀 끝과 흙더미만 보인다. 커스텀 창 왼쪽에는 이동 시연을 추가하지 않고 유형 선택 창에서만 시연한다.

날개형은 충전 1회당 0.4초(평지에서 약 6타일) 비행한다. 공중에서 스페이스를 새로 누르면 충전 1회를 추가로 써 남은 비행 시간에 0.4초를 더한다. 자동 출구 이동 중에는 해당 경로를 해제하고 새 0.4초 비행으로 돌아간다. 착지 위치와 모션 시간을 초기화하지 않으며 추가 무적은 부여하지 않는다. 비행 중에는 충전 회복을 일시 정지하고 착지 후 이어서 회복한다. 시연은 비행 1/2, 2/2 입력 표시로 두 번의 연속 비행을 보여 준다.

횟수형 능력과 대시 대체 능력의 충전 소모는 `SpendTravelCharge`를 공유한다. 사용 시 완성된 충전 1회만 줄이고 회복 중인 부분 충전은 유지한다. 예를 들어 1회 + 회복 50%에서 사용하면 0회 + 회복 50%가 된다. 완충 시에는 회복 타이머를 비우며, 충전 완료 시 남는 시간은 다음 충전에 이월한다.

## 이동 규칙

| 유형 | 일반 물/깊은 물 | 늪지대 물 | 용암 | 암벽 |
|---|---|---|---|---|
| 날개형 | 가능 | 가능 | 가능 | 불가 |
| 물살형 | 가능 | 가능 | 불가 | 불가 |
| 굴파기형 | 불가 | 불가 | 불가 | 가능 |

물살형은 물 진입 탐색부터 이동 중 충돌 판정까지 같은 규칙을 적용한다. 몸 중심뿐 아니라 충돌 반경 안의 지형도 검사한다.

날개형의 지속시간이나 굴파기/수영 게이지가 끝나면 당시 위치에서 가장 가까운 통과 가능한 출구를 찾는다. 진행 방향과 1.5타일 제한 없이 로드된 지형에서 최단 경로를 찾고, 경로를 따라 출구까지 이동한다. 물살형의 용암 금지와 각 유형의 충돌 규칙은 경로 탐색에도 적용한다.

6개 유형의 잔상은 유형 도입 전 대시 설정으로 통일했다: 0.03초마다 한 장, 0.22초 유지, 시작 불투명도 70%에서 선형으로 감소한다. 이동 거리마다 여러 장을 덧붙이지 않는다. 쏙쏙형은 순간이동 구간에 다섯 장만 두며 출발 쪽은 더 빨리 흐려진다. 게임과 시연은 `TravelTypes`의 같은 잔상 상수를 사용한다.

유형 선택 창은 SPACE 입력 표시, 지형, 실제 위치 이동과 수정된 잔상을 함께 시연한다. 시연 이동 폭은 기존 290에서 148로 줄이고, 버튼과 시연 사이 간격을 늘렸다. 바닥은 점 형태 대신 연결된 지면 단면이며 날개형/물살형은 둑과 물, 굴파기형은 짧은 암벽을 보여 준다. 이동 중 공격 입력은 버퍼링하며, 공격 준비 중 이동 능력을 쓰면 공격을 이동 뒤로 이어받는다. 얼굴과 목 픽셀을 변형해서 전환하지 않는다.

## 생성 캐릭터

`DesignAi.HeroSheetPrompt`가 선택된 유형을 4열 × 3행 시트의 마지막 행에 지정한다. 얼굴·눈·의상 일관성과 실제 팔다리 동작을 명시한다. 마지막 행은 진입, 이동 A, 이동 B, 마무리 순서다.

유형 변경으로 기존 시트가 8프레임만 남았다면 영웅 외형을 다시 요청하지 않아도 생성 버튼에서 이동 행을 다시 만든다. 빠진 이동 셀도 이미지 작업 실패로 보고한다. 실제 유료 API 생성은 오프라인 검사에서 호출하지 않는다.

## 버튼

`GameButtonStyle`는 9-slice 프레임과 hover/pressed/disabled 상태를 역할별로 제공한다.

- Primary: 청록색 이중 장식, 시작·이어하기·적용
- Category: 보라색 잘린 모서리와 발광 테두리, 유형 선택·설정·탭
- Craft: 금색 두꺼운 하단, 생성·구매·강화
- Secondary: 차분한 얇은 금속 테두리, 뒤로·닫기
- Choice: 유형별 색상과 선택 테두리
- Danger: 붉은색, 삭제·포기

버튼 이름에 따른 자동 스타일 지정은 제거했다. 타이틀, 세계 선택, 사망 화면과 뒤로/닫기 버튼은 기존 프레임을 사용한다. 커스텀 창의 유형 선택, 생성, 시작, 유형별 선택 버튼만 명시적으로 강조한다. 유형 선택 테두리의 움직이는 네모 알갱이를 제거하고 `ButtonBorderLight`가 프레임 자체에 넓은 빛의 그라데이션과 부드러운 후광을 그린다. 테두리 밖을 도는 별도 입자나 토끼 이미지 재생성은 사용하지 않는다.

## 검증/미리보기

Unity 메뉴 `Diverse → Check Travel Types and Capture Motions` 또는 다음 배치 메서드를 실행한다.

```
Diverse.EditorTools.TravelChecks.RunBatch
```

검사 도구: 물/용암 진입 및 충돌, 몸 반경의 용암 차단, 플레이어의 출구 마무리, 6개 유형의 생성 프롬프트, 원본 얼굴과 목 픽셀 보존, 버튼 프레임. 결과는 `Logs/TravelReview`에 저장한다.

이번 추가 수정은 사용자 요청에 따라 테스트·Unity 실행·새 캡처를 수행하지 않았다. 기존 GIF와 화면 캡처는 이전 수정본의 자료다.

`Tools/review_travel.py`는 Unity가 캡처한 프레임을 그대로 확대·배열해 비교 GIF를 만든다(Pillow 필요). `UIScreenshots.RunBatch`는 유형 선택 창 6종을 포함한 화면 캡처를 저장한다. 두 도구 모두 프레임을 다시 그리거나 생성형 이미지로 대체하지 않는다.
