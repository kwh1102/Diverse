# AI 액티브 · 고정 파츠

## 성장 보상과 후보 선택

Q/W/E/R은 각각 레벨 5/10/15/20에 획득한다. 나머지 레벨업은 T1 파츠를 지급한다. 여러 레벨이 오르면 레벨 순서대로 보상을 받는다. 파츠 32종과 합성 결과 계산은 [Parts.md](Parts.md)를 참고한다. 패시브 기술 언어와 AI 파츠 생성은 사용하지 않는다.

액티브 보상 화면은 해당 슬롯의 독립 후보 3개와 프롬프트 입력창을 제공한다. 카드에는 무기 유형, 슬롯, 조작, 단계별 효과와 대가를 표시한다. 보유 무기 유형을 우선하며 프롬프트로 보유 유형을 지정할 수 있다. 원하는 후보를 고정하면 재요청과 다시 뽑기에서 유지한다. 선택 전에 후보 3개의 아이콘을 한 번에 준비한다. 선택 후에는 게임을 일시정지한 채 해당 후보 하나의 전용 AI 이펙트를 제작·검사한 뒤 장착한다. 실패하면 현재 스킬과 보상을 유지하고 직접 재시도하거나 보류한다.

후보와 고정 상태는 저장한다. 레벨 보상에서 ‘나중에 선택’을 누르면 같은 후보를 보존한다. 대장간에서는 이미 레벨 조건을 충족한 슬롯을 유료로 추가 의뢰할 수 있으며 비용은 선택 시 지불한다. 새 무기를 얻어도 QWER을 자동 생성하지 않는다.

## 액티브 기술 언어 V3

AI는 완성 스킬 목록 대신 **조작 + 전달 방식 + 패턴 + 효과 + 조건 + 타이밍 + 기준 위치 + 연결 사건 + 대가**를 조합한다. 하나의 전술 목적 아래 최대 4단계를 연결한다.

| 구분 | 지원 범위 |
|---|---|
| 조작 | 즉시 시전, 충전 후 해제, 키를 누르는 동안 유지, 같은 키 재입력 |
| 전달 | 베기, 직선, 투사체, 주변 폭발, 지면 영역, 돌진, 후퇴, 순간이동, 방어, 덫, 탄환 장벽 |
| 패턴 | 단발, 부채꼴, 방사, 연쇄, 회수, 관통, 유도, 곡선, 벽 반사, 수렴 |
| 효과 | 피해, 보호막, 회복, 밀치기, 끌어당김, 기절, 표식, 적 탄환 차단 |
| 조건 | 무조건, 표식, 화상, 냉기, 중독 / 조건 상태 소모 |
| 타이밍 | 즉시, 지연, 제한된 반복 |
| 위치 | 시전자, 조준점, 이전 단계 위치, 이전 단계 첫 명중점 |
| 사건 | 즉시 연결, 명중, 도착, 종료, 재입력 |
| 대가 | 긴 후딜, 긴 쿨다운, 짧은 사거리 |

위치와 사건은 앞 단계만 참조한다. 첫 단계는 시전자 또는 조준점에서 시작한다. 명중점은 실제 명중 후에만 사용할 수 있다. 이동은 플레이어 위치에서 시작하며 ‘이전 위치 + 재입력 이동’은 앞 이동의 시작점으로 돌아간다. 충전은 최대 시간에 자동 발동한다. 유지는 키를 누르는 동안 정해진 횟수만 반복하고, 재입력은 대기 중 추가 키 입력을 요구한다.

덫은 정해진 시간 내 적을 감지하면 한 번 발동한다. 장벽은 짧은 선분 주변의 적 투사체를 차단한다. 지형 생성·소환·무제한 루프·다른 스킬 자동 시전은 허용하지 않는다. 투사체 전용 패턴, 이동 단계, 방어 효과의 조합 제한을 검사하고 대상·투사체·반복·동시 시전·최대 시전 시간도 제한한다.

먼저 요청을 지원 동작의 필수 조건으로 해석한다. ‘대시’는 실제 dash 단계를 반드시 포함하며 blink나 이름만으로 충족하지 못한다. 고정하지 않은 모든 후보와 로컬 대체 후보에 같은 조건을 검사한다. 지원 불가·해석 실패·조건 불충족 시 기존 후보를 유지하고 사유를 알린다. 요청에 명시된 동작이 있으면 그 범위 안에서 조작·후속 단계·위치/사건을 다양화하며, 요청이 없는 경우에 후보의 역할을 나눈다: 화력(순간/정밀/지속), 제어(집결/덫), 생존(이동/방어)에서 서로 다른 역할을 배정한다. 고정 후보가 있으면 다른 역할을 우선한다. AI가 적은 역할명 대신 실제 실행 단계에서 역할을 다시 판정한다.

함께 표시하는 후보는 전달 형태·효과·패턴·위치/연결·시간/조건 특징의 집합 거리를 비교한다. 기본 가중치는 실행 그래프 60%, 조작 15%, 역할 25%이고 최소 거리는 0.38이다. 이름·색·원소만 바꿔서는 거리가 늘지 않는다. 최근 생성과 보유 스킬의 정확한 구조 중복도 제외한다. 검사에 실패하면 제한된 횟수로 재설계하고, 연결 실패/형식 실패/계속된 중복에는 해당 역할의 로컬 조합을 사용한다.

‘과정 보기’에는 실제 요청, 역할 배정, 시도 횟수, 실행 규칙/다양성 검사 탈락, 채택된 실행 그래프와 짧은 전술 설명, 로컬 대체, 아이콘·이펙트 검사와 비용을 저장한다. 이야기꾼 답변도 고정 문구 대신 필수 조건·후보별 차이·로컬 대체 여부를 요약한다. 전술 설명은 AI가 출력한 사용자용 설계 요약이며 내부 사고 과정을 요청하거나 재현하지 않는다. 채팅 대화 영역은 현재 입력창/요청 버튼 바로 위까지 늘어나며, 내용이 넘치면 스크롤한다. 설명 본문에는 단계별 동작과 조작/쿨다운/위력/대가를 나누고, 공통 교환 규칙은 카드 하단과 인벤토리의 별도 구역에 표시한다.

AI가 전투 수치를 정하지 않는다. 효과·범위·사거리·패턴·제어·방어·이동의 비용으로 공격력 계수를 계산한다. R은 큰 위력 예산과 긴 쿨다운을 갖는다. 파츠는 액티브 피해·사거리·제어·시전 보호막·적중 회복 등을 보조하며 전체 상한이 적용된다.

## 아이콘과 단계별 전투 이펙트

다음 미수령 Q/W/E/R 보상은 해당 레벨 4단계 전부터 전투 중에 후보 3개와 아이콘을 사전 준비한다. 준비 중에도 전투와 입력은 유지되며 보상 창은 같은 결과를 인계받는다. 아직 준비 중이라면 진행 중인 요청이 끝날 때까지 기다린다. 다음 슬롯 하나만 준비하고 무기/파츠 재장착으로 요청을 반복하지 않는다. 대장간 별도 의뢰는 진행 중인 사전 요청을 마친 뒤 시작한다. 후보와 아이콘 상태를 세이브하며, 중단된 요청은 자동 재결제 없이 로컬 후보/아이콘으로 복구한다. 전용 전투 시트는 선택한 하나만 제작하므로 선택 이후의 이펙트 제작 대기는 남는다. `AbilityRules.active.prefetchSkills`와 `skillPrefetchLeadLevels`에서 조정한다.

실제 아이콘에서 주조색을 추출해 외곽선·음영·주조색·하이라이트 4색을 저장한다. 전투 시트 요청에는 그 팔레트와 아이콘 소재를 함께 전달하며, 기존에 저장된 이펙트도 같은 색으로 맞춘다. AI 그림의 세부 무늬를 실행 동작에 맞는 베기·찌르기·지면 고리·이동 궤적에 입히고 엔진이 시간과 위치를 제어한다. 베기는 무기/몸의 휘두름과 함께 재생하고 지면 효과는 발밑 높이에 둔다. 조준 위치에 투영하는 기존 베기는 원래 판정을 유지하며 손 주변의 시전 궤적을 더한다. 투사체 잔상에는 탄체 복제 대신 소멸 파편을 쓴다. `castVisualDuration`, `impactVisualDuration`, `weaponSwingPixels`, `arcTrailDegrees`, `arcThickness`, `actionHeight`, `movementTrailSpacing`에서 연출을 조정한다. 이미지 한 장의 생성만으로 동작 품질이 완성되는 구조는 아니며, 현재 6프레임 실루엣 보정은 기존 시트의 일부 형태를 단순화할 수 있다.

ActiveSkillArt는 **gpt-image-2.5-flare / low / 1024×1024**로 변경된 후보의 아이콘을 2열×2행 시트 한 장에 요청한다. 위 왼쪽→위 오른쪽→아래 왼쪽을 사용하고 나머지는 비운다. 최종 아이콘은 32px, 12색이다. 고정 후보와 이미 준비한 아이콘은 재사용한다. 이미지 ID는 스킬 아이템을 따라 교환·저장된다. 무기 생성에서 만드는 공격 아트는 평타 전용이다.

작은 실루엣, 큰 픽셀 덩어리, 3~4톤, 부드러운 색과 절제된 입자를 요청한다. 셀 가장자리에서 배경색을 찾아 제거한 뒤 불투명한 테두리·빈 그림·사각 배경을 검사한다. 실패한 셀은 동작에 맞는 로컬 도트를 쓰며 자동 유료 재시도는 하지 않는다. 필요한 경우 인벤토리의 ‘스킬 그림 생성’으로 직접 요청한다.

전투 VFX는 선택한 스킬 하나에 이미지 API를 한 번 호출해 전용 시트를 만든다. 기본 모델은 gpt-image-2.5-flare, 후보 아이콘은 low, 선택 이펙트는 medium이며 AbilityRules.asset에서 변경할 수 있다. 2.6 모델로 자동 전환하지 않는다. 시트는 기존과 같은 1024×1024 한 장이며, 4열에 애니메이션 하나당 한 행을 사용한다. 단계별 동작, 실제 적중에 사용하는 명중, 투사체/이동에 필요한 궤적만 요청한다. 자기 회복·보호막·장벽은 쓰지 않는 명중 그림을 요구하지 않는다. 경계에 연결된 단색/체크 배경은 제거하고 작은 가장자리 접촉은 공통 여백으로 보정한다. 시작·소멸의 빈 프레임은 허용하며 중간이나 투사체 순환의 누락은 같은 AI 애니메이션의 유효 프레임으로 보완한다. 애니메이션마다 서로 다른 유효 프레임이 두 개 이상 있어야 한다. 공통 셀 중심과 크기를 유지한 채 면적 샘플링으로 가는 궤적을 보존한다. 심한 경계 침범·불투명 배경·그림 부족·정지 반복은 행/단계/프레임과 수치를 구분해 실패 사유로 기록한다. 파일 저장까지 마친 후 적용한다. 투사체 본체와 궤적도 전용 프레임을 사용한다. 검사 실패는 자동 재결제 없이 보류한다. 이 검사만으로 시각적 완성도를 보장할 수는 없으며 실제 아트와 연출 확인은 별도다.

이전 스킬과 누락된 그림의 호환 대체로는 로컬 렌더러를 유지한다. ActiveSkillVisuals가 **실행 중인 각 단계**의 전달/효과/패턴/원소에 맞춰 투명 픽셀 애니메이션을 만든다. 베기에는 부채꼴 궤적, 투사체에는 전용 탄체·방사/수렴 발사·궤적, 장벽에는 실제 길이의 선, 덫/영역에는 지면 고리, 이동에는 출발/도착 잔상, 명중에는 파편·끌어당김·표식 등의 모티프를 사용한다. 아이콘이나 다른 무기의 공격 그림을 VFX로 대체 사용하지 않는다. 유한 캐시가 가득 차면 가장 가까운 기존 동작/색의 애니메이션을 재사용하고, 장면 종료 시 텍스처를 해제한다.

후보 텍스트·아이콘 요청 시작 여부·선택한 후보 인덱스·전용 효과 프레임·제작 상태를 저장한다. 유료 응답의 원본 시트와 행 배치·실행 그래프 서명도 검사 전에 저장한다. 처리 규칙이 업데이트되었거나 파일 저장 중 중단된 경우 ‘저장 시트 재처리 (무료)’를 사용한다. 같은 처리 규칙에서 그림 자체가 탈락한 경우 ‘이펙트 새로 생성 (API 비용)’을 명시적으로 눌러야 새로 요청한다. 원본도 매번 다시 생성하지 않으며 자동 유료 재시도는 없다. 이 수정 전에 실패하면서 버려진 원본은 복원할 수 없다. 전용 이펙트 도중 중단되면 자동으로 유료 요청하지 않고 직접 재시도해야 한다. 완성된 프레임이 있으면 재요청 없이 재사용하며 골드와 레벨 보상은 완성 후 장착할 때만 소비한다.

후보 텍스트를 먼저 저장하고 아이콘 요청 시작 여부도 저장한다. 앱이 이미지 요청 도중 종료되면 후보는 복구하되 자동으로 유료 재요청하지 않고 로컬 도트로 마무리한다. 완료된 후보의 과정 로그와 아이콘은 재사용한다.

ImageClient는 응답의 usage로 이미지 입력 텍스트/이미지 토큰과 출력 토큰 비용을 계산한다. usage가 없는 응답은 추정임을 표시하고, 가격표가 없는 모델은 비용 미상 건수로 따로 누적한다. 스튜디오/무기 이미지에도 같은 집계를 적용한다. 요금 근거: [OpenAI 2.5 Flare 모델 문서](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare). 실제 청구액은 공급자 대시보드가 기준이다. 이번 작업에서는 이미지 생성과 실 API 호출을 실행하지 않았다.

## 무기 유형과 교환

유형은 검·활·총·봉·단검이다. 외형과 평타 애니메이션의 WeaponKind와 별도로 관리한다. 각 유형의 QWER·파츠 좌표와 외곽선 색은 데이터에서 정한다. 모든 배치 무기에 실제 칸 모양의 외곽선을 표시하고 사용 중인 무기는 더 두껍게 표시한다. 드래그 미리보기도 같은 실제 칸을 따른다.

교환은 같은 유형·같은 슬롯끼리만 가능하다. **현재 성장 보상과 대장간 추가 의뢰에서는 종속 묶음이 새로 생성되지 않는다.** 후보는 같은 한 슬롯의 독립 대안 3개이며 linkedMask=0을 필수로 검사한다. 등장 확률이 낮은 것이 아니라 획득 경로가 아직 없다. 한 스킬 안의 재입력/명중 후속 단계는 내부 연계이며 Q→W 종속과 다르다. 표식/화상 등에 반응하면서 무조건 쓸 수 있는 기본 동작도 가진 독립 스킬 사이의 시너지는 가능하다. 종속 묶음을 새로 제공하려면 해금된 두 슬롯의 묶음 후보 생성·선택, 이미지 제작, 장착을 함께 처리하는 획득 흐름이 필요하다. 이번 수정에서 그 별도 흐름은 추가하지 않았다. 기존 종속 액티브는 linkedMask와 linkId의 실제 동료 인스턴스를 요구하고 묶음 교환을 유지한다. 양쪽 종속 관계가 이어지면 관련 슬롯 전체를 교환한다. 슬롯 위치와 쿨다운·전용 이미지를 보존하며 종속이 끊긴 스킬은 시전할 수 없다.
