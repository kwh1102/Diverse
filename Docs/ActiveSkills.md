# AI 액티브 · 고정 파츠

## 생성과 실행

완성 스킬 24종을 고르는 방식과 패시브 기술 언어를 제거했다. 파츠는 `Data/AbilityRules.asset → Def / Parts`의 유한 목록을 사용한다. 레벨업 파츠 후보는 이 목록에서 고르며 합성은 같은 종류·같은 등급 두 개를 다음 등급으로 올린다. 중복 파츠는 가장 높은 등급 하나만 적용한다. 자동 공격·분신·재귀 발동은 파츠가 만들 수 없다.

액티브는 `ActiveSkillGenerator`가 플레이 기록, 무기 유형, 최근 구조와 기존 스킬을 읽고 JSON 동작 구성을 새로 생성한다. 일반 스킬은 레벨업·대장간에서 습득할 때, 추가 무기의 QWER은 무기를 받은 뒤 별도로 생성한다. 무기 디자인 생성 요청에는 액티브 능력이나 액티브 이미지를 넣지 않는다.

구성은 **전달 방식 + 패턴 + 효과 + 조건 + 타이밍 + 대가**다. 주효과를 중심으로 최대 3단계, 특수 규칙 최대 2개를 허용한다. 베기·직선·투사체·폭발·지면 영역·돌진·후퇴·순간이동·방어를 피해·보호막·회복·밀치기·끌어당김·기절·표식과 조합한다. 패턴은 부채꼴·방사·연쇄·회수·관통·유도이며, 실행 가능한 조합만 받는다. 반복·대상·투사체·동시 시전 횟수는 데이터의 상한을 따른다. 스킬이 다른 스킬을 자동 시전하지 않는다.

AI가 출력한 숫자로 전투 수치를 정하지 않는다. 효과 개수·범위·사거리·패턴·제어·방어·이동의 비용으로 공격력 계수를 계산한다. 현재 캐릭터 공격력을 기준으로 성장하며, 후딜·긴 쿨다운·짧은 사거리 중 하나의 대가가 붙는다. R은 큰 예산과 긴 쿨다운을 갖는다. 지원하지 않는 구조나 중복은 재요청하고, 실패하거나 AI가 꺼져 있으면 같은 실행 구조의 로컬 조합을 사용한다.

## 전용 이미지

`ActiveSkillArt`는 각 액티브마다 기존 `ImageClient`를 통해 image-2.5 모델을 호출한다. 모델은 `AbilityRules.asset → Def / Active / Image Model`에서 조정한다. 기본값은 기존 게임과 같은 `gpt-image-2.5-flare`다. 기존 API 키·엔드포인트·이미지 품질 설정을 사용한다.

각 스킬에 독립된 3열×2행 시트를 요청한다. 셀은 아이콘, 투사체, 시전/베기, 명중, 궤적, 발사 효과다. 도트화한 이미지 ID를 해당 스킬 아이템에 저장한다. 무기 평타의 전역 그림을 액티브에 상속하지 않는다. 교환·저장·불러오기에도 전용 아트가 따라간다. 투사체는 시전 당시 전용 아트를 보유하며 다른 무기로 바꾸면 남은 효과를 종료한다.

이미지 실패 시 해당 스킬의 임시 도트를 쓰며, 인벤토리의 **스킬 그림 생성**으로 다시 요청한다. 생성 도중 저장한 스킬은 로컬 조합과 대기 상태를 보존하고 이어하기에서 다시 생성한다. 파츠 이미지는 API를 호출하지 않고 `Resources/Sprites/Parts`의 고정 PNG를 사용한다.

## 종속과 교환

검·활·총·봉·단검은 유한한 유형이다. 무기 외형과 평타 애니메이션의 `WeaponKind`와 분리한다. 유형별 QWER 좌표와 파츠 좌표는 `AbilityRules.asset → Def / Weapon Shapes`에 있다.

같은 유형, 같은 슬롯끼리만 교환한다. 독립 스킬은 하나씩 옮길 수 있다. 표식이 없어도 기본 기능을 갖는 연계는 독립이며, 특정 동료의 표식이 꼭 필요한 종속은 `linkedMask`와 `linkId`로 묶는다. 생성되는 종속은 최대 두 슬롯이고, 생산자와 소비자가 같은 그룹을 명시해야 한다. 표식은 그룹마다 분리해 다른 무기의 표식으로 대체할 수 없게 한다.

교환 시 양쪽 무기의 종속 관계를 반복 확장해 이동할 슬롯을 결정한다. 예를 들어 Q·R과 W·R이 부딪히면 Q·W·R을 함께 교환한다. 이때 Q는 Q, W는 W, R은 R 위치를 유지한다. 쿨다운·그림·그룹 ID는 아이템과 함께 이동한다. 실패와 드래그 미리보기는 배치를 되돌리고, 연결이 끊긴 스킬은 시전하지 못한다. 종속 파츠가 아니라 **종속 액티브**만 묶음 규칙을 쓴다.

## 저장 호환과 에디터

이전 패시브 프로그램은 실행하지 않고 안정적인 ID 해시로 고정 파츠에 대응시킨다. 이전 24종 액티브 ID는 로컬 조합으로 이관한다. 기존 3×3 배치는 유형별 공간으로 다시 배치하고, 공간이 부족한 아이템은 수령 대기에 보존한다. 사용자 저장 파일을 개발 도구에서 직접 수정하지 않는다.

- 능력·파츠·무기 공간: `Assets/_Project/Data/AbilityRules.asset`
- 가방·합성·계승 비용: `Assets/_Project/Resources/GameDatabase.asset → Inventory`
- UI: `Assets/_Project/Prefabs/UI/GameCanvas.prefab → HUD / SkillBar`, `Inventory`, `PartFusion`, `Evolve`
- 고정 파츠 이미지: `Assets/_Project/Resources/Sprites/Parts`, 미리보기 `ArtSource/Parts/catalog.png`

사용자 요청에 따라 이번 작업에서는 Unity 실행, 컴파일, 테스트, 실 API 호출을 수행하지 않았다.
