# 환경 애니메이션

기존 오브젝트 PNG, 피벗, 크기, 충돌과 배치를 유지하며 바람·빛·수면과 작은 효과 레이어를 추가한다. 광장/초원을 포함한 9개 프로필과 외부 8개 지역 모두 적용한다.

## 표현

| 대상 | 움직임 | 원본 유지 방법 |
|---|---|---|
| 나무/큰 잎/덤불/갈대 | 밑부분 고정, 위쪽으로 갈수록 바람에 휨 | 기존 텍스처의 UV만 몇 픽셀 이동. 월드 좌표를 공유해 바람이 지나가며 개체마다 위상 차이가 생김 |
| 깃발/바람 표식 | 기둥과 아래쪽 고정, 천 끝의 물결 | 기존 천 이미지의 자유단만 변형 |
| 수정/거울/등불/얼음 | 작은 빛 띠와 느린 맥동 | 고정 이미지 안의 색을 낮은 강도로 변화. 수정/선인장을 나무처럼 휘지 않음 |
| 모닥불/화로 | 4프레임 불꽃, 느린 연기 | 원본 물체 위에 공용 효과 시트를 덧그림 |
| 워프스톤 | 내부 회전과 중심으로 모이는 작은 빛 | 돌의 원본을 유지하고 내부 에너지만 별도 레이어로 표시 |
| 물/용암/독성 물 | 작은 물결/맥동, 드문 기포/연기 | 이미 구운 지면에 저해상도 마스크로 동적 표현. 지형을 매 프레임 다시 베이크하지 않음 |

숲은 잎 색의 작은 입자, 화산은 재와 상승 연기, 수정은 차가운 작은 빛, 빙하는 눈, 협곡은 바람에 흐르는 모래 알갱이, 요새는 깃발/등불, 거울은 반짝임, 늪은 갈대와 낮은 대비의 부유 입자를 사용한다. 단단한 바위/건물/선인장은 안정적으로 유지한다.

## 데이터와 최적화

- `WorldRules.asset → environment`: 전체 켜기/끄기, 프레임 속도, 바람/수면 속도, 생성 예산, 입자 수/수명, 오브젝트별 동작 규칙.
- `Data/Themes/*.asset → environment`: 테마별 바람/천의 강도, 반짝임, 입자 색·속도·크기·빈도.
- 물체별 규칙은 정확한 키 또는 끝의 `*` 접두사로 연결하며 앞의 구체적인 규칙을 먼저 적용한다. 예: `tree_Dunes_*`는 정지, `tree_Crystal_*`는 반짝임, 나머지 `tree_*`는 바람.
- 식생/깃발/수정은 개별 애니메이션 Update나 개별 머티리얼을 만들지 않는다. 테마·동작별 머티리얼을 공유하고 GPU에서 시간/월드 좌표를 사용한다. 캐릭터 가림용 기존 `SceneryOcclusion`은 유지한다.
- 불꽃/연기/물방울/포탈 효과 16프레임은 128×128 공용 텍스처 한 장과 Sprite 래퍼 4개를 사용한다. 원본 큰 생성 시트는 `ArtSource/`에만 있어 빌드에 들어가지 않는다.
- 액체가 있는 청크만 16×16 RGBA 마스크 1장(픽셀 데이터 1KiB)을 갖고, 청크가 파괴되면 해제한다. 절벽의 투영 면은 정적으로 남긴다. 기존 바닥 텍스처 재사용/시간 분할 베이크를 유지한다.
- 월드 컨트롤러 하나가 최대 4종의 네이티브 ParticleSystem을 공유한다. 동시에 살아 있는 환경 입자는 합계 64개, 생성은 100ms당 최대 2개, 발생기 검사도 틱당 24개로 제한한다.
- 화면 근처의 발생기만 방출한다. 파괴된 발생기는 순환 검사 중 제거한다. 매 프레임 전체 오브젝트 검색, 텍스처 재생성, 입자용 GameObject 생성/파괴를 하지 않는다. 입자 시스템과 머티리얼은 월드 로딩 때 준비한다.
- 게임 일시정지에는 환경 시계와 네이티브 입자도 멈춘다. 환경 시간은 셰이더의 전역 값 한 번으로 전달하며 빛/수관/시트가 함께 정지한다.
- 기존 모닥불의 프레임 수에 비례하던 랜덤 불티는 새 환경 효과가 켜지면 비활성화한다. 전투 Fx 풀을 환경 효과로 채우지 않는다.

## 확인

`Assets/_Project/Scenes/Game.unity`를 열어 Play를 다시 시작한다. 에셋 설정을 바꾼 뒤에도 Play를 재시작해 규칙/머티리얼 캐시를 갱신한다. **Diverse → World → Apply Environment Animation**은 환경 설정을 초기값으로 재설치하므로 일반 확인만을 위해 실행할 필요는 없다.

원본과 내장 image_gen 최종 프롬프트는 `ArtSource/Environment/README.md`, 실행용 시트는 `Assets/_Project/Resources/Environment/ambient.png`다.

검증 도구:

- `EnvironmentDefaults.RunBatch`: 시트 가져오기, 셰이더 오류, 16개 프레임, 팔레트/알파/텍스처 용량, 강체 분류, 기존 8개 지역 배치/청크 검사.
- `EnvironmentCapture.RunBatch`: 실제 Game 씬의 8개 지역을 여러 시점으로 렌더하고 원본 Sprite/밑동 위치·길찾기·일시정지·입자 상한을 검사.
- `EnvironmentCapture.RunBatchPreview`: 숲/화산의 8fps 미리보기 프레임과 밀집 발생기/화면 밖 방출 검사를 실행.
- `PerfProbe.RunBatchEnvironmentOff`와 `PerfProbe.RunBatch`: 같은 게임 흐름에서 환경 애니메이션 정지/활성 비교. 에디터 프레임 시간과 `Diverse.Environment` CPU 구간을 기록하며 단독 빌드의 GPU 프로파일과 구분한다.
- `SmokeTest.RunBatch`: 메뉴→게임(전체 무기/프리팹/오버레이)→사망→메뉴→이어하기.

모든 실행 검사는 별도 임시 저장을 사용한다. 결과와 실제 화면은 `Logs/Environment/`, 성능 로그는 `Logs/EnvironmentPerfOff.log`, `Logs/EnvironmentPerfOn.log`에 둔다.

## 측정 결과 (2026-11-02)

- 시트 16프레임의 팔레트·이진 알파·Point 필터·밉맵 없음·CPU 복사본 해제 검사 통과. 실제 파일 5,051바이트, RGBA GPU 픽셀 데이터 64KiB. 물 마스크는 색 보정이 적용되지 않는 Linear 데이터 텍스처다.
- 8개 지역의 실제 GPU 렌더에서 시간에 따른 픽셀 변화, 원본 Sprite/밑동 위치 유지, 장소 접근 경로, 일시정지 시 환경 시계 정지 확인. 숲/화산은 8fps 미리보기용 24프레임을 추가 촬영했다.
- 40개 추가 발생기와 긴 연기로 부하를 가한 경우 활성 입자 최대 64/64개. 카메라를 옮기고 지역 부유 입자를 끈 검사에서 화면 밖 발생기의 새 방출은 0개였다.
- 메뉴→게임(모든 무기·프리팹·오버레이)→사망→메뉴→이어하기 검사 통과. 실제 사용자 저장은 사용하지 않았다.

| 에디터 20초 측정 | 애니메이션 정지 | 활성 |
|---|---:|---:|
| 이동 평균 / p95 | 16.7 / 16.8ms | 16.8 / 16.8ms |
| 전투 평균 / p95 | 16.7 / 16.8ms | 16.7 / 16.9ms |
| 이동 최대 / 33ms 초과 프레임 | 41.1ms / 2회 | 66.9ms / 2회 |
| 전투 최대 / 33ms 초과 프레임 | 24.9ms / 0회 | 45.8ms / 3회 |
| 검사 중 일시정지 프레임 | 0 | 0 |

이동 거리는 정지/활성 각각 78.5/82.5타일, 새 청크는 15/18개로 경로와 작업량이 완전히 같지는 않다. 환경 제어 CPU 구간은 평균 0.00~0.01ms로 기록됐다(표시 반올림 포함). 활성 이동의 최장 프레임은 `Diverse.Chunks`에서 65.3ms를 기록했으며, 청크 준비·생성 중의 간헐적 지연은 남아 있다. 실제 해상도/기기에서 지연이 없음을 보장하는 측정은 아니다.

별도 고정 화면 960×600의 최종 렌더+GPU 읽기 중앙값(4회 워밍업 뒤 20회)은 숲 정지/활성 3.78/3.85ms, 화산 3.81/3.78ms였다. CPU와 읽기 비용이 포함되고 실행별 변동이 있으므로 순수 GPU 프레임 시간이나 성능 향상 수치로 해석하지 않는다. 원시 기록은 `Logs/Environment/render_benchmark.txt`, 프레임별 구간 기록은 `EnvironmentPerfOff.txt`/`EnvironmentPerfOn.txt`에 있다.

기존 성능 검사는 전투 중 자동 진화 화면이 열리면 멈춘 상태를 측정할 수 있어, 검사용 경험치 문턱을 고정하고 일시정지 프레임을 기록하도록 보완했다. 이 조정은 검사 도구에만 적용된다.
