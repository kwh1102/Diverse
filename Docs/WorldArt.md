# 월드 아트 개편 (2026-11-02)

## 시각 기준

세피리아 참고 화면처럼 귀여운 비율, 둥근 실루엣, 큰 색 덩어리와 단계적인 명암을 사용한다. 미세한 사실적 묘사, 디더링, 그라데이션은 사용하지 않는다. 배경에도 재질과 경계의 손질이 있어야 하며, 바닥의 대비는 캐릭터와 적보다 낮게 둔다.

- 16 PPU, 정면 축의 탑다운 RPG 표현. 지면 축은 가로·세로이고 절벽을 가로로 비틀지 않는다.
- 한 절벽 단은 16px. 높이와 윗면·벽면·모서리·충돌은 같은 지형 정보에서 결정된다.
- 자연 지형의 큰 발자국은 2타일 단위로 움직인다. 모서리를 3px 깎고, 직선 경계에는 최대 1px의 짧은 요철을 넣는다.
- 잔디, 길, 포장 등의 재질은 넓은 구획으로 연결한다. 유적을 타일별 랜덤 포장으로 그리지 않는다.
- 요새의 낮은 땅과 절벽 윗면은 별도 재질이다. 윗면 재질은 `ThemeDef.cliffTop`, 벽 재질은 `ArtStyle.cliffs`에서 편집한다.
- 광원은 왼쪽 위. 외곽선·색 단계·접지 그림자를 공통 팔레트로 맞춘다.

## 배경 재질 보완

첫 개편에서 지나치게 비워진 단색 면과 기계적인 선을 보완했다. 기존 캐릭터·적·오브젝트 시트는 다시 가져오지 않는다. 배경은 연결과 높이를 정확히 유지해야 하므로 별도 대형 그림을 덮는 대신 기존 네이티브 픽셀 렌더러에서 그린다.

- 잔디·흙·모래: 낮은 대비의 불규칙한 색 덩어리, 여러 형태의 풀·작은 꽃·자갈·모래결을 군집으로 그린다. 한 픽셀씩 흩뿌리는 노이즈는 쓰지 않는다.
- 포장: 크기와 줄눈이 일관된 돌에 면별 미묘한 색 차이, 모서리 깎임·음영·짧은 균열·부분적인 이끼를 넣는다.
- 물: 가늘고 길이가 다른 물결, 낮은 대비의 수면 변화, 물가의 얕은 수심과 끊어진 포말을 겹친다. 물가 전체를 같은 흰 선으로 두르지 않는다.
- 다리: 실제 길·샛길 방향을 기준으로 판자를 놓고, 나뭇결·이음매·옹이·가장자리 보와 기둥을 같은 바닥 안에 그린다. 길이 꺾이거나 사선일 때 실제 통행 영역을 그대로 따른다.
- 절벽: 윗면의 풀 덮개와 아래로 내려오는 끝, 흙 속에 박힌 돌·층리·광물면을 지역 재질에 맞춘다. 일직선 띠 하나로 높이를 끝내지 않는다.
- 눈·얼음·화산·수정·거울·늪: 눈이 쌓인 결, 짧은 얼음 균열, 검은 돌의 파편, 광물 조각, 작은 반사면과 젖은 흙을 구분한다.

`TileBakerBiomes.cs`가 표면의 색 덩어리와 재질별 도트를, `TileBakerEdges.cs`가 물가·재질 전이·다리 가장자리를 그린다. 재질 마스크와 가까운 이웃의 거리/방향은 베이크 때 계산해 두며, `TileBakeOperation`은 이 버퍼도 보존하므로 중간에 검토용 렌더가 실행되어도 결과가 같다. 작은 요철은 화면 표현이며 충돌·이동 가능 타일은 바꾸지 않는다.

`ArtStyle.asset`의 각 GroundLook에 `undertone`/`overtone`을 추가했다. 기존 팔레트 색의 값과 인덱스는 유지하고 배경용 중간색을 뒤에 더해 기존 스프라이트의 색을 바꾸지 않는다. `groundDetail`, `groundFringe`, `shoreWidth`, `surfacePatchSize`로 밀도·가장자리·얕은 물 폭·색 덩어리 크기를 조정한다. **Diverse → Art → Apply Background Material Pass**는 배경 설정만 재적용하며, 전체 아트 가져오기도 같은 설정을 사용한다.

## 원본과 실제 게임 에셋

`ArtSource/WorldOverhaul/`에는 최종 생성 원본 5장과 프롬프트, 관리 목록을 둔다. 게임은 이 큰 원본을 로드하지 않는다. `WorldArtOverhaul`이 실제 픽셀 크기와 팔레트로 변환한 `Assets/_Project/Resources/Sprites/*.png`를 사용한다.

- 자연물 9개 지역, 지역 장식, 마을 건물·소품, 8개 랜드마크를 교체한다.
- 일반 적 9종·보스 3종은 대기/이동/준비/피격/반대 걸음의 5프레임 계약을 유지한다. 이동은 픽셀 단위 발 이동과 상하 움직임, 준비는 눌리는 실루엣으로 구분한다.
- 주인공의 10포즈와 6개 코스튬, 노인·주민·주요 NPC도 같은 표현을 사용한다. 무기는 손에 별도로 붙는다.
- 베기/피격 이펙트는 코드로 그리는 매개변수 기반 그림을 유지하되, 랜덤한 픽셀 소실 대신 이어진 형태로 축소하고 파티클 색을 팔레트에 맞춘다. 변경은 전투 판정이나 AI 패턴을 바꾸지 않는다.
- PNG 교체 시 `.meta` GUID를 유지한다. 일반 다시 그리기는 `managed.txt`의 최종 아트를 덮어쓰지 않는다.

생성 시트의 셀 경계는 정확한 등분이라고 가정하지 않는다. 실제 투명 여백에서 행·열 경계를 찾아 이웃 물체나 밑동이 잘려 들어오는 현상을 막는다. 바이너리 알파, 팔레트, 16 PPU, Point 필터를 검사한다.

## 배치 규칙

8개 지역의 군집·환경물 크기·소품 묶음·분기 도로 개편은 [지역 공간 구성](WorldComposition.md)을 따른다. 아래의 초기 배치 설명 중 이미지 전체의 비겹침 규칙은 새 프로필에서 밑동/간격 검사와 수관 부분 겹침으로 대체된다.

테마별 소품 확장, 큰 장소와 기록/보물 탐험, 눈 깜빡임·상자 상태 수정은 [탐험 확장](Exploration.md)을 따른다. 배경 재질 표현 위에 장소 구성과 탐험 동선을 추가하며, 기존 아트 원본과 새 원본의 가져오기 순서도 보존한다.

`World/SceneryLayout.cs`는 월드 좌표에 고정된 후보를 만든 뒤, 주변 후보의 우선순위와 실제 스프라이트 크기를 비교한다. 이웃 청크가 아직 없더라도 결과는 같다.

1. 마을, 구조물·출입 공간, 길 주변은 비운다.
2. 물·절벽 가장자리에 밑동이 걸치지 않게 전체 바닥 범위를 검사한다.
3. 같은 높이에 놓인 이미지 사이에 여유 공간을 둔다. 높은 지형과 낮은 지형의 의도한 가림은 별개다.
4. 식생은 숲/빈터 군집에 따라 배치한다. 돌바닥 한가운데의 덤불·나무는 제한한다.
5. 잔풀은 지면에 구워서 그린다. 풀 한 포기마다 GameObject를 만들지 않는다.
6. 유적은 중앙 진입로와 열주, 숲 공터는 일정 간격의 나무와 꽃 군집으로 구성한다.

`WorldRules.asset`의 `sceneryCell`, `sceneryGap`, `sceneryRoadMargin`에서 조정한다. 실제 후보 검사와 역순 검사 도구는 `WorldVisualChecks`에 있다.

## 큰 지형과 스트리밍

산맥 간격·존재 범위·높이 문턱을 조정해 연결된 큰 지형이 더 자주 등장한다. 월드 골격 → 랜드마크 → 큰 지형/길 → 재질 → 장식 순서와 5방향 전투/환경 테마 분리는 유지한다.

같은 시드의 새 결과는 로딩 순서에 상관없이 결정적이다. 이번 개편은 지형 생성 규칙 자체를 바꾸므로 이전 버전과 지형 모양까지 동일하지는 않다. 실제 사용자 세이브 파일은 마이그레이션 도구나 검증 도구가 수정하지 않는다.

`TileBaker`는 같은 출력의 두 경로를 제공한다.

- 시작/워프/검토: 동기 베이크.
- 이동 중: `TileBaker.Operation`이 기본 2ms 예산으로 나눠 베이크하고, 완성된 텍스처만 청크에 연결한다. Unity 객체는 메인 스레드에서만 다룬다.

절벽은 열 단위 탐색 테이블, 바닥은 재질/이웃 캐시를 사용한다. 프레임마다 청크 대기열을 다시 탐색하지 않는다. 청크 언로드 시 생성된 Sprite 래퍼를 해제하고, 지면 텍스처는 기존 제한된 재사용 캐시로 돌려준다.

## 에디터에서 확인

`Assets/_Project/Scenes/Game.unity`를 열고 Play. 데이터 조정은 `Data/ArtStyle.asset`, `Data/WorldRules.asset`, `Data/Themes/*.asset`에서 한다.

- **Diverse → Art → Apply Cute World Overhaul**: 원본에서 현재 아트와 규칙 재적용. 명시적으로 실행하는 초기화 명령이므로 Inspector에서 조정한 해당 아트 설정은 재설정된다.
- **Diverse → Art → Check World Overhaul**: 에셋, 청크 접합, 장식 간격/결정성, 시간 분할 결과 검사.
- **Diverse → Art → Capture All Terrain Regions**: 실제 Game 씬의 9개 지형, 마을, 8개 보스 랜드마크를 `Logs/AllTerrain/`에 촬영.
- 이전 첫 아트 패스와 비스듬한 절벽 복원 명령은 **Art → Legacy** 아래에 둔다.

검증 명령 (`Unity.exe`는 설치된 6000.0.62f1 사용):

```text
-batchmode -nographics -projectPath . -executeMethod Diverse.EditorTools.WorldArtOverhaul.RunBatchValidated -logFile Logs/WorldOverhaulValidated.log
-batchmode -projectPath . -executeMethod Diverse.EditorTools.AllTerrainCapture.RunBatch -logFile Logs/WorldOverhaulCapture.log
-batchmode -projectPath . -executeMethod Diverse.EditorTools.SmokeTest.RunBatch -logFile Logs/WorldOverhaulSmoke.log
-batchmode -projectPath . -executeMethod Diverse.EditorTools.PerfProbe.RunBatch -logFile Logs/WorldOverhaulPerf.log
```

검사 결과: `Logs/Redesign/checks.txt`, `Logs/World/report.txt`, `Logs/PerfProbe.txt`. 게임 흐름·스크린샷·성능 테스트는 별도 검증용 저장 경로를 사용한다. 에디터 측정 시간은 GPU를 포함한 실제 빌드 FPS와 구분해 해석한다.

첫 전면 개편 검증:

- 293개 스프라이트의 팔레트·바이너리 알파·16 PPU·Point 필터 검사 통과. 기존 에셋 GUID 변경 없음.
- 9개 지역의 청크 접합 픽셀 불일치 0개. 장식 1,087개 표본에서 같은 높이의 실루엣 겹침 0개이며 역순 검사 결과도 동일.
- 시드 12345·777·4242에서 주요 장소 접근 불가 0곳, 시드별 4,000타일 결정성 불일치 0개. 산지 비율 10.0~14.7%.
- 분할 렌더와 동기 렌더의 픽셀 결과 일치. 2ms 예산에서 최대 래스터 구간 2.13ms(마지막 4행 블록 포함).
- 실제 Game 씬의 9개 지역·마을·8개 랜드마크 촬영과 메뉴 → 게임 → 사망 → 메뉴 → 이어하기 검사 통과.
- 에디터 이동 20초(82.2타일, 새 청크 28개)와 전투 20초에서 각각 평균 16.7ms, 33ms 초과 프레임 0개. 단독 빌드나 다른 하드웨어의 성능 보장 수치는 아니다.

배경 재질 보완 후 검증:

- 실제 9개 지역·마을·8개 랜드마크와 초원/협곡의 실제 강·목조 다리를 다시 촬영했다. 11개 지형/다리 위치에서 통합 영역과 개별 청크의 픽셀 불일치 0개.
- 9개 지역의 역순 청크 검사, 장식 1,087개 간격 검사, 기존 293개 스프라이트 검사 통과. 검토 렌더가 중간에 실행되어도 시간 분할 결과 일치.
- 표본 분할 베이크 준비 2.11ms, 최대 래스터 구간 2.06ms. 20개 실제 청크 동기 베이크 평균 12.32ms(에디터 CPU, GPU/텍스처 업로드를 포함한 프레임 시간과 구분).
- 실제 이동 20초(71.4타일, 새 청크 20개)와 전투 20초 모두 평균 16.7ms. p95는 각각 17.1/17.3ms였으며 33ms 초과 프레임은 각각 2/1회, 최대 55.1/39.0ms였다. 간헐적 지연이 없다고 단정하지 않는다. 원본 기록은 `Logs/BackgroundMaterialPerf.log`, `Logs/PerfProbe.txt`에 있다.
- 이전 배경 캡처는 `Logs/BackgroundPass/Before/AllTerrain/`, 현재 캡처는 `Logs/AllTerrain/`. 실제 세이브는 사용하지 않았다.

이전 `Art.BakeGround`와 그 전용 경계 혼합 코드는 제거했고, 기존 `DesignPerf` 진입점은 현재 렌더러를 측정하도록 연결했다. 과거 원본은 `ArtSource/`에 기록으로 보존해 게임에서 로드하지 않으며, 이름만 보고 다른 기능의 파일을 삭제하지 않는다.
